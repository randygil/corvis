# Design

## Context

Current behavior, read in the code of this worktree:

- **Startup.** `CorvisApplication::bootstrap` (`crates/corvis/src/application.rs:95-123`) runs `Container::scan` and
  then `instantiate_all` (`:108-112`) and returns any `DiError` (logged first, `:114-122`).
  `TestingModuleBuilder::compile` goes through the same function. `Container::scan`
  (`crates/corvis/src/di/container.rs:191-251`) already validates the graph statically: exported tokens must exist
  (`:230-241`, `DiError::InvalidExport`).
- **Transient providers are skipped.** `instantiate_all` (`container.rs:402-420`) continues past every provider whose
  scope is `Scope::Transient` (`:407-409`). A transient provider is only constructed when something resolves it
  (`resolve_provider`, `:329-370`, which never caches it, `:337-342`, `:358-360`). A singleton that injects a transient
  provider constructs it during `instantiate_all`, so only transient providers that no singleton injects escape
  validation.
- **How a missing field dependency is reported today.** The generated constructor resolves each field through
  `ResolveCtx::resolve_dependency` (`crates/corvis/src/di/injectable.rs:111-133`). When `lookup` finds nothing it
  returns `DiError::UnknownDependencies { requester, deps, token, index, module }`. `deps` is the field list with `?`
  at the missing index, built from the names the macro passes to `with_dependencies` (`injectable.rs:71-76`). An alias
  (`Provider::use_existing`, `crates/corvis/src/di/provider.rs:237-246`) resolves its target through
  `Container::resolve`, which returns `DiError::NotFound { token }` when the target is not visible
  (`container.rs:320-323`). `Option<Arc<T>>` fields use `get_optional`, which yields `None` when the token is not
  visible (`injectable.rs:94-103`).
- **What the macro knows.** `injectable_impl` (`crates/corvis-macros/src/injectable.rs:15-140`) walks the fields:
  `#[init]`/`#[default]` fields are not resolved (`:36-41`, listed as `"-"` in `deps`, `:48-52`).
  `#[inject(token)]` on a non-`Arc` field uses `inject_cloned` (`:65-68`), a required dependency on the token. Every
  other field goes through `Probe::<T>::new().__corvis_inject_kind().resolve(..)` (`:59-63`, `:71-76`). Autoref
  dispatch in `crates/corvis/src/__private.rs:40-76` picks `InjectTag` for types implementing `InjectField`
  (`Arc<T>`, `Option<Arc<T>>`, `ModuleRef`; `injectable.rs:157-187`) and `DefaultTag` (`T::default()`) otherwise. The
  generated impl provides `construct`, `hooks` and, for transient classes, `scope` (`:95-99`, `:104-132`). The same
  expansion serves `#[controller]`, `#[module]` and `#[websocket_gateway]`.
- **Provider kinds.** `Provider` (`provider.rs:110-118`) stores token, name, an opaque `factory`, scope, hooks and
  enhancer. `use_class` / `class` (`:131-150`), `use_class_as` (`:154-169`) and the `app_*` constructors
  (`:258-284`) wrap `T::construct`. `use_value[_arc]` (`:171-192`) has no dependencies. `use_factory[_arc]`
  (`:194-234`) runs arbitrary code. `use_existing` (`:236-246`) depends on one token. `scope()` (`:248-252`) can make
  any of them transient.
- **Hand-written `Injectable` impls**: `default_injectable!` (`crates/corvis/src/__private.rs:368-381`, no
  dependencies) and `OrmService` (`crates/corvis-orm/src/module.rs:169`).
- **Docs.** `docs/fundamentals/injection-scopes.md:40` says transient providers "are not created at startup"; nothing
  says their dependencies are not checked.
- **Port apps**: no `scope = "transient"` or `Scope::Transient` anywhere in `corvis-tests/corvis/*`.

## Goals / Non-Goals

**Goals:**
- A missing required dependency of a transient class provider or alias fails startup with the same error as at first
  use.
- Nothing is instantiated by the check, so constructor side effects and the "not created at startup" rule are kept.
- Existing hand-written `Injectable`/`InjectField` implementations compile unchanged.

**Non-Goals:**
- Validating factory providers (their dependencies are code, not data).
- Statically validating singletons (instantiation already does it).
- Changing error texts (issue #14 rewords `UnknownDependencies`; the shared helper of decision 4 picks that up).

## Decisions

1. **The macros generate a static dependency description.** New public types in `crates/corvis/src/di/injectable.rs`
   (re-exported from `corvis::di`):
   ```rust
   /// The injected fields of an `#[injectable]` class, generated by the macros.
   pub struct Dependencies { pub requester: &'static str, pub names: &'static [&'static str], pub items: Vec<Dependency> }
   pub struct Dependency { pub token: Token, pub index: usize, pub optional: bool }
   ```
   `Injectable` gains `fn dependencies() -> Option<Dependencies> { None }` (`None` = not declared, never validated).
   `injectable_impl` emits it with the same `requester`/`names` it already passes to `with_dependencies`, and one item
   per field:
   - `#[init]`/`#[default]` → none;
   - `#[inject(tok)]` on a non-`Arc` field (the `inject_cloned` path) → required `Token::from(tok)`;
   - every other field → `(&Probe::<T>::new()).__corvis_inject_kind().dependency::<T>(token, index)`, using the same
     autoref dispatch as construction. `InjectTag::dependency` calls a new provided method
     `InjectField::dependency(token, index) -> Option<Dependency>` (default `None`), implemented for `Arc<T>`
     (required), `Option<Arc<T>>` (optional) and left as `None` for `ModuleRef`. `DefaultTag::dependency` returns
     `None`.
   `default_injectable!` declares an empty list.
   - Alternative: instantiate transient providers once at startup and drop the instance. Rejected: it runs
     constructors with side effects and contradicts the documented "not created at startup" rule (and #15's spec).
   - Alternative: a dry-run `ResolveCtx` that records lookups instead of resolving. Rejected: generated constructors
     need real values to continue past the first field, and factories can branch on values.
   - Alternative: parse field types syntactically in the macro (`Arc<..>`, `Option<Arc<..>>`). Rejected: type aliases
     and the `Default` fallback make syntax unreliable; the `Probe` dispatch is what construction already uses, so the
     two cannot disagree.

2. **`Provider` carries what it knows.** New field `pub(crate) deps: DeclaredDeps` with
   `enum DeclaredDeps { Unknown, Fields(Dependencies), Alias(Token) }`. Value providers use `Fields` with an empty list.
   `use_class`, `use_class_as` and `app_*` take `T::dependencies()` (`Unknown` when `None`). `use_existing` uses
   `Alias(existing)`. `use_factory[_arc]` uses `Unknown`. Testing overrides already replace the whole `Provider`
   (`Scanner::add_provider`, `container.rs:93-109`), so the override's description is the one checked.

3. **Check after scanning, before instantiation.** `Container::validate_transients(&self) -> Result<(), DiError>`
   runs at the end of `Container::scan`, next to the export validation, before the container is returned. For each
   module in id order and each provider in registration order with `Scope::Transient`, a depth-first walk:
   - `Fields`: for each item, `lookup(module, token)`. Missing and required → error. Missing and optional → skip.
     Found a transient provider → walk it in its owner module. Found a non-transient provider → stop (instantiation
     validates it).
   - `Alias(t)`: missing → `DiError::NotFound { token }`; found transient → walk it.
   - `Unknown`: stop.
   A `path` of `(module, token)` detects cycles (`DiError::Circular`, chain built as in `resolve_provider`,
   `container.rs:343-347`), and a `done` set makes the walk linear. The first error is returned; ordering is
   deterministic.
   - Alternative: run it in `bootstrap` between `scan` and `instantiate_all`. Equivalent; `scan` is preferred because
     it already holds the other static graph checks and is the single entry point.
   - Alternative: run it after `instantiate_all`. Rejected: singleton constructors with side effects would run first
     for a graph that is already known to be invalid.

4. **Identical error text.** Extract the `UnknownDependencies` construction of `resolve_dependency`
   (`injectable.rs:116-131`) into a crate-private helper taking `requester`, `names`, `index`, `token` and module name.
   Both the check and `resolve_dependency` use it, so the startup message is byte-for-byte the message a first
   resolution would produce, including any rewording from #14.

## Risks / Trade-offs

- [Applications that start today with a broken, never-resolved transient provider stop starting] → intended. The
  ports have none. The error names the provider, token and module.
- [`#[inject(expr)]` token expressions are now also evaluated in the synchronous `dependencies()` function] → an
  expression that only works inside the async constructor (uses `.await` or the hidden `__ctx`) would fail to compile.
  Documented tokens are literals and constants. If this shows up, the macro can fall back to not declaring that field.
- [Transient factory providers stay unchecked] → documented on the injection scopes page, with the advice to prefer
  class providers when early validation matters.
- [New public items in the DI API] → small, documented as macro output; open question about hiding them.

## Open questions

1. Should `Dependencies`, `Dependency` and the two provided methods be `#[doc(hidden)]` (macro support only) or
   documented public API (useful for hand-written `Injectable` impls such as `OrmService`)? Proposed: public and
   documented, since hand-written impls can opt in.
2. Should `OrmService`'s hand-written `Injectable` (`crates/corvis-orm/src/module.rs:169`) declare its dependencies in
   this change? Proposed: no; it is a singleton, so the check never reaches it.

## Review notes (2026-11-08)

- `Dependencies` and `Dependency` are `#[doc(hidden)]` (macro support, not public API).
- `OrmService` declares its dependencies if it is built through `Injectable`; otherwise leave it.

## Implementation notes

- **Aliases**: #15 added `Provider::alias_of`, so `DeclaredDeps` has only `Unknown` and `Fields`; an alias declares its
  target through `alias_of` instead of a third variant. `validate_transient` follows `alias_of` first. A non-transient
  alias of a transient target is transient too (`Container::is_transient` follows the chain), so it is validated.
- **Hidden types**: `Dependencies`, `Dependency`, `Injectable::dependencies` and `InjectField::dependency` are
  `#[doc(hidden)]` (review note). `OrmService` is a hand-written singleton and was left unchanged.
- **Check location**: `Container::validate_transients` runs at the end of `Container::scan`, before the container is
  returned, so it runs before any instantiation.
- **Macro**: the field description uses the same `Probe` dispatch as construction. `#[inject(expr)]` on a non-`Arc`
  field declares a required dependency on the token; no existing expression failed to compile in the workspace.
- **Tests**: `transient_validation.rs` (15 tests) and a unit test in `provider.rs`. Resolving a transient provider
  through the testing module needs the provider exported by its module, so the fixtures export it.
- The corvis-parity task 6.6 is left for the maintainer.
