# cli/new Specification

## Purpose
What `corvis new` generates: a project that builds, tests and runs, with the defaults a new application should
start from (route posture enforced, the root route marked public).

## Requirements

### Requirement: New projects enforce route posture
The project generated by `corvis new` SHALL enable route posture in enforce mode in its `main` (by calling
`require_route_posture()` before `listen`), and every route it generates SHALL be either guarded or marked
`#[public]`, so the generated project starts as generated and `corvis posture` exits with status 0 for it.

#### Scenario: Generated project starts
- **WHEN** a project is created with `corvis new my-app`, with a framework dependency that resolves (the published
  version matching the CLI, or `--corvis-path` pointing at a framework checkout), and run without changes
- **THEN** it starts and serves `GET /` as before

#### Scenario: Generated project passes the report
- **WHEN** `corvis posture` runs in a project created with `corvis new` and not modified
- **THEN** it lists `GET /` (`AppController::get_hello`) as public and exits with status 0

#### Scenario: Route added without a guard
- **WHEN** a route with no guard and no `#[public]` is added to the generated `AppController` and the project is run
- **THEN** the application refuses to start with the route posture error that names the new route

### Requirement: New projects depend on the published framework by default
When `corvis new` runs without `--corvis-path`, without `--corvis-version` and with `CORVIS_PATH` unset or empty, the
generated `Cargo.toml` SHALL declare every framework crate it depends on with a version requirement equal to the CLI's
own version without build metadata, and MUST NOT contain a `path` for any framework crate. The result MUST NOT depend
on the folder the CLI was compiled from.

#### Scenario: Default dependency
- **WHEN** `corvis new my-app --skip-git` runs with `CORVIS_PATH` unset, using a CLI whose version is `0.1.0`
- **THEN** `my-app/Cargo.toml` contains `corvis = { version = "0.1.0" }` and no `path =` entry

#### Scenario: CLI installed from crates.io
- **WHEN** a CLI installed with `cargo install corvis-cli` runs `corvis new my-app`
- **THEN** the generated dependency is the version requirement of the installed CLI, and `cargo build` in `my-app`
  resolves `corvis` from crates.io

#### Scenario: Hint when the build checkout exists
- **WHEN** the default version requirement is written and the `crates/corvis` folder of the checkout the CLI was
  compiled from exists
- **THEN** `corvis new` prints a `NOTE` line that names that folder and the `--corvis-path` flag and `CORVIS_PATH`
  variable that would use it, and the generated `Cargo.toml` still contains the version requirement

### Requirement: A local framework checkout is used only on request
`corvis new` SHALL write a path dependency (`corvis = { path = "<dir>" }`) only when `--corvis-path <dir>` is given or
the `CORVIS_PATH` environment variable is set and not empty, and SHALL write the given requirement when
`--corvis-version <requirement>` is given.

#### Scenario: Path from the flag
- **WHEN** `corvis new my-app --skip-git --corvis-path /src/corvis/crates/corvis` runs
- **THEN** `my-app/Cargo.toml` contains `corvis = { path = "/src/corvis/crates/corvis" }`

#### Scenario: Path from the environment
- **WHEN** `corvis new my-app --skip-git` runs with `CORVIS_PATH=/src/corvis/crates/corvis`
- **THEN** `my-app/Cargo.toml` contains `corvis = { path = "/src/corvis/crates/corvis" }` and the output has a `NOTE`
  line saying that `CORVIS_PATH` was used

### Requirement: Dependency options have a fixed precedence
A command-line flag (`--corvis-path` or `--corvis-version`) MUST take precedence over `CORVIS_PATH`. Giving both
`--corvis-path` and `--corvis-version` MUST fail before any file is created.

#### Scenario: Flag beats the environment
- **WHEN** `corvis new my-app --skip-git --corvis-version 0.2` runs with `CORVIS_PATH` set
- **THEN** `my-app/Cargo.toml` contains `corvis = { version = "0.2" }`

#### Scenario: Conflicting flags
- **WHEN** `corvis new my-app --skip-git --corvis-path ../corvis --corvis-version 0.1` runs
- **THEN** the command exits with a non-zero status, the error names both flags, and no `my-app` folder is created

### Requirement: Dependency values are validated
A path from `--corvis-path` or `CORVIS_PATH` MUST be rejected when it contains a double quote or a control character,
and a `--corvis-version` value MUST be rejected when it is not a Cargo version requirement. The error MUST name the
flag or variable the value came from, and no project folder is created.

#### Scenario: Unsafe path from the environment
- **WHEN** `corvis new my-app --skip-git` runs with `CORVIS_PATH` containing a double quote
- **THEN** the command fails with an error that names `CORVIS_PATH`, and no `my-app` folder is created
